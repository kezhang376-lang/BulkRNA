## 2. kubernetes.account 的精确定义

```yaml
kubernetes:
  context: null
  namespace: "default"
  shell_pod: "zk1-med-6ff4f46898-rlbtd"
  r_pod: "zkr1-med-5d8b8c5b48-tggbt"
  account: "zhangke"
```

account 是两个 Pod 内应使用的 Linux 账号。它不改变集群认证用户，不是 `kubectl --user` 参数，也不修改 Pod securityContext 或自动创建用户。

已增加以下保护：

1. 模板与 schema 声明 account，准备器拒绝缺失、不合法或 root 账号。
2. Shell worker 在调用工具、检查数据和创建结果之前，验证当前有效 UID、实际用户名和目标账号 UID。
3. R Linux worker 在读取分析数据/写结果之前做同类核验。
4. 当前 UID=0、目标账号 UID=0（即使用户名不是root）、用户名或 UID 不匹配时立即停止；不回退成 root。
5. 带 account 的真实项目不允许在 Windows 上误作 Pod 分析执行；Windows 无 Pod 账号配置的合成测试夹具只用于测试统计代码。

**尚未实现自动远程登录或自动账号切换。** 字段不会使普通 kubectl exec 自动变成指定用户。应在已授权的远程阶段验证 Pod 中账号存在、UID非0、HOME/PATH/R库/软件环境和目录权限；若默认进程是 root，先通过 Pod 支持的账号切换机制启动指定账号，再调用入口。不能切换时停止，不修改 Pod 配置绕过要求，不以 root 继续。

例如，Pod 支持 runuser 时，可由后续执行器在容器内使用 `runuser -u zhangke -- ...`；这个命令只作为接口说明，本轮未执行。实际工具可用性及用户软件环境尚未验证。参考：[kubectl exec 官方参数](https://kubernetes.io/docs/reference/kubectl/generated/kubectl_exec/)、[runuser 手册](https://www.man7.org/linux/man-pages/man1/runuser.1.html)。

### 元数据格式与研究范围

目前两份文件是“整行放进引号”的形式：

```text
"sample_id,group"
"10GY5FFRT-1,10GY5FFRT"
```

CSV解析后变成一列，不能识别 sample_id/group。正确的逗号CSV应类似：

```csv
sample_id,group
10GY5FFRT-1,10GY5FFRT
```
