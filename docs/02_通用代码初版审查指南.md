# 通用代码 v1：实现范围与审查指南

日期：2026-10-27。此版本供代码审查和小规模验证，不代表正式分析已获授权。原始 `step1_shell.sh`、`step2_Rscript.R` 与项目现有配置/样本表均保留。

初版项目审查包为 `projects/20261018_xiehe_zhou/prepared/review_v2/`，状态为 BLOCKED；`review_v1` 为早期开发快照。此后账号约束和项目配置已升级，这两个旧包均不代表当前代码，不得直接执行。见 [配置升级记录](04_项目配置升级与账号约定.md)。初版测试及局限见 [本地验证记录](03_初版本地验证记录.md)。

## 1. 本版实现方式

采用“通用代码 + 项目配置 + 每次运行的独立快照”，不为每个项目重新写一套统计逻辑。项目准备器生成一份冻结通用代码、配置、元数据和运行入口的包；定制科研代码仍应放在项目 custom 中单独审查。

| 文件 | 职责 |
|---|---|
| `workflow/orchestrator/prepare_project.R` | 默认/项目配置合并、schema 子集校验、元数据和设计检查、阻断报告、独立运行包；仅本地读写 |
| `workflow/orchestrator/Prepare-BulkRNA.ps1` | Windows 调用准备器的便捷入口，自动寻找唯一 R 安装或显式指定路径 |
| `schemas/config.schema.json` | 本版接受的字段、类型和取值；未知字段拒绝；条件约束另在准备器检查 |
| `config/review.example.yaml` | 扩展配置示例，未知真实信息保留 null，不改用户项目配置 |
| `scripts/shell/run_shell.sh` | Linux Bash 入口，要求显式 check-only/execute 参数 |
| `scripts/shell/shell_stage.py` | Python 标准库调用 fastp/STAR/featureCounts/samtools，可选 MultiQC；解析和验收输出 |
| `scripts/R/common.R` | 严格 counts、样本/比较验证、表达表和图形输出公共函数 |
| `scripts/R/qc.R` | 库大小、logCPM分布、相关性、PCA、距离聚类，可选批次展示 |
| `scripts/R/differential_expression.R` | 单次 DESeq2 拟合、多比较、完整基因表、标准化 counts、MA/火山图、模型保存 |
| `scripts/R/enrichment.R` | 每比较独立 GO GSEA、GO ORA（上下调分开）、映射诊断、完整/显著通路表和 RDS |
| `scripts/R/custom_plots.R` | 可独立调用的指定基因图、指定 GO 曲线函数，不被标准流程自动执行 |
| `scripts/R/run_analysis.R` | R 阶段入口：预检查、状态和日志，不依赖之前交互会话对象 |
| `tests/test_shell_stage.py`、`tests/test_R.R` | 本地解析、阻断、设计及模拟 counts 验证，不访问集群 |

## 2. 与原代码的对应和必须审查的改变

### 保留的主线

- fastp → STAR → featureCounts → raw counts → QC/DESeq2 → GO GSEA。
- STAR 输出坐标排序 BAM，并保留 TranscriptomeSAM/GeneCounts 参数；这不代表片段长度模块已验证。
- 原始整数 counts 进入 DESeq2，一次拟合服务全部比较；原始 log2(CPM+1)保留为描述性 QC。
- 低表达过滤保留 `legacy_nonzero_fraction` 候选，精确对应 `rowSums(counts>0) >= floor(fraction*ncol(counts))`。不会自动强制该规则；也支持显式 `none` 或 `min_count_samples`，改变规则需确认。
- 默认比较表字段沿用当前项目的 `contrast_id,treatment,control`；正 log2FC 表示 treatment 相对 control 上调。

### 程序性修复

- 不再用固定行号解析 fastp JSON 或 STAR 日志，不再通过 sed 猜样本列名。
- counts 表保留原始样本字符，显式按 sample_id 对齐，不依赖元数据行序。
- 所有比较和图形从当前显式输入获取数据，不引用上一循环残留的 gse/anno。
- 保留 padj NA 等状态和完整统计量；SYMBOL 注释另存，不扩增基因级主表。
- 每次新建 run 目录，已有/部分输出拒绝覆盖；失败保留日志和状态。
- GO 空集、无匹配基因及自定义单基因绘图有独立处理，不降低阈值制造结果。

### 需要科研确认的选择（没有对真实项目实施）

1. **FDR/效应值**：候选实现按当前 YAML 的 `padj < fdr` 且 `abs(log2FC) > cutoff` 作事后筛选；普通 Wald 检验、BH，不执行效应阈值检验或 LFC shrinkage。与原始 p<0.01、FC>1.5 不等价。
2. **计数单位**：本版明确限定 PE fragment，要求支持 `-p --countReadPairs` 的 featureCounts；显式 -s 0/1/2 必须来自已确认建库信息，不猜测。
3. **fastp**：暂用直接调用 fastp 与白名单参数，未复制未知 start_fastp.py/旧 config 的行为；`extra_args: []` 是 fastp 软件默认行为，不能宣称与旧 wrapper 等价。真实参数未确认前不得正式运行。
4. **模型**：本版只支持由分类元数据列构成的加性设计（例如 `~ group`、`~ batch + group`）；连续变量、交互和复杂对比暂不支持。每组至少2样本是 v1 输入限制，不是统计功效保证。
5. **离群与拟合**：不自动替换离群 counts，保留 Cook's 筛查；如 DESeq2 自动将指定的 dispersion fit 改成另一种，本版拒绝接受结果并报错要求审查，而不静默换方法。
6. **QC**：PCA 使用显式 logCPM，输入为未预过滤 raw counts；DE 使用配置的预过滤 counts。没有隐含 TMM/VST、批次校正或异常样本删除。
7. **GO GSEA**：候选保留 log2FC 排序，可配置 Wald stat。显式 fgsea backend、seed、eps，不传原 nPerm；这是算法参数差异，须确认。保留 ties 并报告，不抖动打散。
8. **GO ORA**：新增模块，按上/下调分别计算，以 padj 可评估且可映射基因为背景；背景和方向策略需确认，不默认全基因组。
9. **ID**：本版原样使用 ENSEMBL，无版本后缀自动截断和重复聚合；遇到映射不足报告诊断，需依据真实 ID 制定规则。GO库来自安装的 OrgDb，记录包版本，不等于 Ensembl_109 的全部注释内容。

## 3. 当前限制：明确拒绝而非假装支持

- KEGG、Reactome、Hallmark、饱和度、片段长度、核心富集基因热图、复杂设计和远程后台调度未接入。
- 模式 B 只提供可调用的自定义绘图函数，尚无计划确认后的自动调度；模式 C、模块级指纹恢复未实现。
- v1 要求 `execution.mode: standard`、`resume: false`、`overwrite: false`。不应为通过检查而自行关闭用户想做的分析；当前 KEGG=true 会明确阻断，需讨论先实现或调整本轮范围。
- FASTQ 输入只支持 gzip PE，且 fastp/STAR/featureCounts 必须一起启用。counts 输入可用于全新 R 分析，但不是证明既有 DE 结果可复用的模式 C。
- FASTA、GTF、STAR index 的完整一致性、足够内存/空间和跨 Pod 共享存储仍需远程预检查；当前脚本只检查存在性和部分内容，没有声称已完成参考版本认证或资源调度。
- Shell 必须有 Python>=3.9、Bash、fastp、STAR、samtools、合适版本 featureCounts、zcat；MultiQC 仅 `analysis.multiqc: true` 时调用。
- R 至少需要 yaml/jsonlite（本地准备），以及按模块所需 DESeq2、edgeR、ggplot2、pheatmap、clusterProfiler、enrichplot、AnnotationDbi 和物种 OrgDb。不自动安装或升级。
- 运行包当前假定两个 Pod 能访问相同绝对 run_root；尚不支持不同挂载路径转换。确认共享存储之前不得启动。
- 工具默认参数会随版本变化，运行中记录版本，但最终还需固定已验收版本/镜像。
- 代码/配置快照采用 MD5 文件校验清单，目的是检查意外改动，不是安全签名或可恢复执行证明。大 FASTQ 的 size/mtime 仅为记录，不代表内容哈希。
- R/Python 状态文件和日志帮助排错，不是完整后台作业管理器；掉线后不要直接重新启动。

## 4. 运行包内容与命令

准备器的命令仅生成本地文件，不运行计算，也不会调用 kubectl：

```powershell
& 'C:/Program Files/R/R-4.2.3/bin/Rscript.exe' --vanilla `
  workflow/orchestrator/prepare_project.R `
  projects/20261018_xiehe_zhou/config.yaml `
  review_002 `
  projects/20261018_xiehe_zhou/prepared/review_002
```

也可用 PowerShell 入口（PowerShell 执行策略若禁止脚本，不自动修改系统策略，改用上述 R 命令）：

```powershell
./workflow/orchestrator/Prepare-BulkRNA.ps1 `
  -Config projects/20261018_xiehe_zhou/config.yaml `
  -RunId review_002
```

已有输出目录会拒绝，使用新 run_id/目录。存在阻断项时仍写出审查包并返回非零状态；先阅读 review_plan.md，而不是把非零误认为分析失败。

```text
prepared/<run_id>/
  config.original.yaml
  config.resolved.yaml
  runtime.json                 # Linux路径、参数、阻断项；不要手工清空 blockers
  samples.original.txt
  contrasts.original.txt
  samples.tsv
  contrasts.tsv
  review_plan.md
  bundle_checksums_md5.csv
  code/R/...
  code/shell/...
  run_shell.sh
  run_R.sh
```

每次准备都复制当时的代码。修改源代码后须生成新运行包，旧包不会自动跟随更新；不得误用旧快照。生成 Bash 入口使用 UTF-8/LF。

Linux 上传和执行仍需另行授权及准备，当前没有自动发布器。部署后默认入口为检查模式：`bash run_shell.sh`、`bash run_R.sh`；显式 `--execute` 才会计算。两阶段分别执行，Shell 成功且 counts 验收后再进入 R；本轮不执行这些命令。配置无阻断只代表本地形式检查通过，仍需要远程核验和正式启动授权。

R counts 接口为严格 TSV：第一列 `gene_id`，其余列为完全匹配样本表的非负整数计数。标准 Shell 自动产出 `results/runs/<run_id>/shell/counts/raw_counts.tsv`；不是旧脚本目录下任意一个同名文件。

## 5. 你审查时建议先看这些地方

1. `config/review.example.yaml`：哪些参数同意、哪些需要改，特别是链特异性、过滤、fastp、FDR/FC、GO ORA/GSEA。
2. `scripts/R/differential_expression.R`：设计、方向、阈值和结果完整性。
3. `scripts/shell/shell_stage.py`：FASTQ输入、fastp参数、STAR、featureCounts计数口径。
4. `scripts/R/enrichment.R`：排序、背景、ID映射、空结果和每比较溯源。
5. 当前项目最新审查包的 `review_plan.md`：补齐真实输入，逐项消除阻断；不直接手改生成包掩盖问题。

确认后优先做已有参数和新代码之间的小规模对照；实际 FASTQ/Pod 测试通过前，不称为生产可用。
