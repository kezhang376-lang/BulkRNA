# 新结果目录规则（2.0.0正式版）

本次只改变新运行的输出目录接口和命名，不改变分析方法、样本、阈值或软件环境。已发布v1.0.0、旧冻结运行包、运行日志和服务器结果保持原样。2026-10-28已完成新项目真实Pod运行及验收，正式发布到main和v2.0.0；发布证据及限制见docs/10_V2发布说明与验收记录.md。

## 目录与命名

```text
项目根目录/
├── raw_data/
├── workflow/
│   └── v2.0.0_20261027_run01/          # 冻结运行包
└── results/
    └── v2.0.0_20261027_run01/          # 新运行结果，无runs层
        ├── launcher/                  # 启动锁、PID、后台日志
        ├── bam_count_data/            # 整个Shell阶段
        │   ├── clean/
        │   ├── bam/<sample_id>/
        │   ├── counts/raw_counts.tsv
        │   ├── qc/
        │   ├── logs/
        │   └── status.json
        └── gene_expr_data/             # 整个R阶段
            ├── qc/
            ├── gene_diff_expr/
            │   └── <contrast_id>/
            ├── enrichment/
            ├── report.html
            ├── analysis.log
            └── status.json
```

各阶段原有的配置、版本、参考、命令及统计记录继续位于对应阶段目录，文件名未更改。launcher/shell.launch.json与r.launch.json等表示阶段身份，保留原名；源代码目录scripts/shell及配置analysis字段也不改名。

命名格式为`v<流程版本>_<YYYYMMDD>_run<至少两位正整数>`。例如v2.0.0_20261027_run01、run02、run100；run00、无效日期、与VERSION不一致的版本均拒绝。日期表示该次运行标识中指定的日期，不强制等于执行当天。序号由调用者明确选择，程序不猜测、递增或覆盖已有运行。

VERSION为2.0.0，表示本次发布的不兼容输出接口；配置schema_version仍为1.0-review，不要求用户更改科研配置。运行包目录、tar.gz基本名、服务器workflow子目录和结果目录必须与run_id一致。

## 本地准备示例（不上传、不运行）

在项目根目录，用本机可用的Rscript执行：

```powershell
Rscript --vanilla workflow/orchestrator/prepare_project.R projects/20261018_xiehe_zhou/config.yaml v2.0.0_20261027_run01 projects/20261018_xiehe_zhou/prepared/v2.0.0_20261027_run01
python workflow/orchestrator/package_bundle.py projects/20261018_xiehe_zhou/prepared/v2.0.0_20261027_run01 projects/20261018_xiehe_zhou/prepared/v2.0.0_20261027_run01.tar.gz
```

Rscript/Python应替换为本机实际安装的解释器路径。上述日期及序号只是示例；若目录已存在应使用新编号，不删除旧结果强行重跑。准备完成仍需独立授权远程检查、上传及正式计算。

新runtime.json记录pipeline_version、output_layout_version=2.0，以及固定的run_root=paths.output_dir/run_id。新源码拒绝旧布局runtime；旧结果需用原冻结代码查看，不存在自动迁移或按目录猜测的兼容回退。run_id命名并不会增加断点恢复能力。
